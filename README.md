# Software Engineering Archive

> **Archivo académico de ejercicios, prácticas, proyectos, experimentos y aprendizajes desarrollados durante nuestra etapa de Ingeniería de Software en la Universidad CUE Alexander von Humboldt.**

Este repositorio nació como un espacio para guardar código.

Con el tiempo terminó convirtiéndose en algo un poco más interesante: un **registro de nuestra evolución como estudiantes y desarrolladores**, donde quedan reunidos ejercicios, prácticas, proyectos, experimentos, documentación y pequeños fragmentos de las cosas que fuimos construyendo mientras aprendíamos.

No pretende ser únicamente una colección de archivos. Es, sobre todo, una **bitácora técnica de una etapa**.

---

## 01 — Sobre este archivo

`Software Engineering Archive` reúne parte del trabajo realizado durante nuestra formación en Ingeniería de Software.

Aquí conviven ejercicios pequeños con proyectos más completos, código experimental con trabajos académicos, documentación con prototipos y soluciones que probablemente hoy escribiríamos de otra manera.

Y eso es precisamente parte del valor del repositorio.

El código no está aquí solamente para demostrar que algo funciona. También conserva **cómo aprendimos a hacerlo**.

Con el tiempo, este archivo permite observar una evolución natural:

```text
primeros ejercicios
        ↓
prácticas
        ↓
proyectos
        ↓
experimentos
        ↓
mejores estructuras
        ↓
más criterio técnico
```

Es un repositorio para consultar, estudiar, comparar, corregir y, eventualmente, mirar hacia atrás.

## 02 — Qué encontrarás aquí

El archivo puede contener, entre otras cosas:

| Área          | Contenido                                                                    |
| ------------- | ---------------------------------------------------------------------------- |
| Ejercicios    | Problemas, talleres y prácticas de programación                              |
| Proyectos     | Aplicaciones y trabajos desarrollados durante la formación                   |
| Experimentos  | Pruebas de concepto, ideas y desarrollos en fase exploratoria                |
| Juegos        | Minijuegos y proyectos interactivos                                          |
| Documentación | Guías, manuales, presentaciones y material académico                         |
| Parciales     | Entregas, evaluaciones y trabajos relacionados con la actividad académica    |
| Portafolios   | Proyectos web y trabajos personales desarrollados durante la etapa formativa |

La estructura podrá evolucionar con el tiempo. La intención es mantenerla **simple, legible y suficientemente flexible** para acompañar varios semestres sin convertirse en un laberinto de carpetas.

## 04 — Organización

La estructura busca separar el contenido por propósito y facilitar la navegación desde GitHub, VS Code, terminales Linux, Git Bash y otros entornos de desarrollo.

La organización principal se construye alrededor de las distintas asignaturas, prácticas y proyectos de la formación.

Como parte de esa organización, algunos módulos cuentan con documentación propia para explicar:

* qué se estudió;
* qué tecnologías aparecieron;
* qué proyectos se desarrollaron;
* qué documentación se utilizó;
* cómo evolucionó el trabajo;
* y qué quedó aprendido al finalizar cada etapa.

## 05 — Una cápsula del proceso

Este repositorio también conserva algo que normalmente desaparece cuando un proyecto se termina:

**el proceso.**

Una solución inicial puede ser imperfecta.

Un proyecto puede tener una estructura que hoy ya no usaríamos.

Un ejercicio puede contener código que posteriormente aprenderíamos a escribir de forma más limpia.

Eso no convierte esos archivos en basura.

Los convierte en evidencia de evolución.

Por eso, este archivo intenta conservar una parte del recorrido en lugar de presentar únicamente una versión artificialmente pulida del pasado.

```text
Lo que funciona
        +
Lo que aprendimos
        +
Lo que tuvimos que corregir
        +
Lo que hoy haríamos diferente
        =
Historia técnica
```

## 07 — Filosofía del archivo

Este repositorio sigue una idea bastante sencilla:

> **Guardar hoy aquello que quizá queramos entender dentro de unos años.**

No todo lo que hay aquí pretende ser software de producción.

Hay ejercicios.

Hay experimentos.

Hay proyectos universitarios.

Hay cosas pequeñas.

Hay cosas que seguramente podrían hacerse mejor.

Y justamente por eso merece la pena conservarlas.

Un archivo académico no debería mostrar solamente el resultado final; también debería permitir observar **el camino que llevó hasta él**.

---

## 08 — Documentación

A medida que el archivo crece, la documentación irá más allá de los README individuales.

La intención es construir documentación por asignatura y por etapa académica, incluyendo cuando sea relevante:

* contenidos estudiados;
* lenguajes y herramientas;
* proyectos desarrollados;
* líneas de tiempo;
* estadísticas del repositorio;
* distribución tecnológica;
* referencias académicas;
* materiales de estudio;
* contribuciones;
* observaciones sobre el proceso de aprendizaje.

De esta forma, el repositorio funciona simultáneamente como:

**archivo de código + biblioteca académica + bitácora técnica + memoria del proceso.**

---

## 09 — Estado del archivo

Este repositorio es **histórico y evolutivo**.

No representa una colección estática.

A medida que avance nuestra formación, podrán aparecer nuevas asignaturas, nuevos lenguajes, nuevos proyectos y nuevas formas de trabajar.

La estructura puede cambiar.

Los proyectos pueden crecer.

Los README pueden mejorar.

Y, probablemente, parte del código será reemplazado por versiones mucho mejores.

Eso está bien.

La idea no es que el archivo permanezca congelado.

La idea es que **conserve la historia mientras seguimos avanzando**.
